# 스튜디오 편집기 구조 개편 — 확정 계획 (2026-09-25)

조사 보고(2026-09-25)와 해성 결정을 합친 **고정 계획**이다. 단계마다 하나만 끝내고 브라우저로 확인한 뒤 다음 단계로 간다.
단계 순서·범위를 바꿀 때는 이 문서를 먼저 고친다.

## 1. 새 구조 요약

- **⓪ 시작 화면**: 사진 준비(1688 가져오기·내 사진 올리기)가 끝나면 두 카드 — [원클릭 AI 자동 제작](주황, 완전 자동) / [직접 만들기](반자동, 기본).
  편집기 라우트(`studio-editor`)에서 `studio_projects.page`가 비어 있을 때 띄운다 → 기존 가져오기·업로드 흐름은 고치지 않는다.
- **① 편집기**: 작업 화면 전체 어두운 색, 작업물만 원래 색.
  상단바 / 왼쪽 아이콘 막대(템플릿·구간·사진·텍스트·요소·배경합성·저장값) / 왼쪽 패널 / 가운데 긴 페이지 / 오른쪽 [미니뷰 | 레이어].
  사진 위에는 선택 테두리 말고 아무것도 올리지 않는다.
- **② 페이지 속 사진 클릭**: 왼쪽 패널이 사진 속성 패널로 바뀐다. 빠른 조작은 우클릭 메뉴·Delete 키.
- **③ 지우기 화면**: 사진 한 장 전용 화면(Fabric). 지금 편집기의 붓·네모·AI(LaMa)·단색을 옮겨 쓴다.
- **작업 순서 자유**: 지운 결과는 페이지 자리가 아니라 사진(`studio_images.edit` + `patches/` PNG)에 저장 → 템플릿을 바꿔도 남는다.
- **페이지 문서 모양(`studio_projects.page`, v:1 — 자세한 것은 `src/lib/studioPage.js` 맨 위)**:
  `{ v: 1, width: 780, gap, sections: [ { id, height, bg, items: [ { id, type, imageId?, x, y, w, h, rotation, opacity, flipX, flipY, locked, hidden, 꾸미기 칸?, groupId? } ] } ], parked: [imageId] }`
  `groupId`(9단계, 선택 칸) = 같은 값끼리 한 그룹. 없으면 그룹 아님. 한 구간 안·구성원 2개 이상만 (어긋나면 읽을 때·바꾼 뒤 풀림)
  글자 요소(10-1단계) = `{ id, type: 'text', x, y, w, h, rotation, opacity, flipX, flipY, locked, hidden, groupId?, text, fontFamily, fontSize, fontWeight, color, align, lineHeight, letterSpacing }`
  — text(\n = 줄바꿈) · fontFamily(허용 목록 키, 예 'noto-sans-kr') · fontSize 8~400px · fontWeight(그 폰트가 가진 값만) · color '#rrggbb' · align left|center|right ·
  lineHeight 0.8~3.0배 · letterSpacing -0.2~1.0em. h는 자동(줄 수 × fontSize × lineHeight). 빠지거나 잘못된 값은 readPage가 기본값으로(`studioText.js` 맨 위)
  글자 꾸미기 칸(10-2단계, 기본값 = 모두 없음): strokeWidth 0~20 · strokeColor · shadowX·shadowY -40~40 · shadowBlur 0~40 · shadowColor · shadowOpacity 0~1 ·
  bgColor '#rrggbb' 또는 ''(없음) · bgOpacity 0~1 · bgPadding 0~60 · bgRadius 0~100. 줄바꿈·h에 영향 없음
  도형 요소(11-1단계) = 공통 칸 + `type: 'shape'` + shape('rect'|'ellipse'|'triangle'|'star') · fill('#rrggbb' 또는 '' = 없음) · fillOpacity 0~1 ·
  strokeWidth 0~40(0 = 없음, 안쪽으로 그림) · strokeColor · radius 0~400(rect만). 기본값 rect · #111111 · 1 · 0 · #000000 · 0
  선 요소(11-1단계) = 공통 칸 + `type: 'line'` + strokeWidth 1~40 · color · dash('solid'|'dashed'|'dotted') · startCap·endCap('none'|'arrow'|'dot').
  x·y·w = 선 길이의 가로 네모, rotation = 선 각도, h = 누르는 두께 영역(굵기·끝 모양에 맞춰 자동). 모양·기본값은 `studioShape.js` 맨 위
  사이즈표 요소(11-2단계) = 공통 칸 + `type: 'table'` + cells(문자열 [행][열], 행 1~20·열 1~10, 칸 한 줄·30자) · headerRow(true|false) ·
  fontFamily(글자와 같은 허용 목록) · fontSize 8~80 · color · headerBg · headerColor · cellBg · borderColor('#rrggbb') · borderWidth 0~6 · align(left|center|right, 기본 center).
  h = 행 수 × round(fontSize × 2.2) 자동, 열 폭 = w ÷ 열 수, 최소 폭 = 열 수 × 24. 모양·기본값은 `studioTable.js` 맨 위
  강조 배지(11-2단계)는 새 type이 아니다 — 도형 1개 + 글자 1~2개를 같은 groupId로 넣는다(프리셋 `studioBadge.js`)
  **겹침 순서(11-2)**: 화면 앞뒤 = 구간 items 배열 순서(뒤가 앞). 페이지·미니뷰 모두 요소마다 z-index = 배열 자리 + 1, 구간(그림 상자) = 쌓임 맥락(isolation: isolate) —
  선택 테두리·손잡이·달라붙기 안내선은 구간 바깥 형제라 늘 요소 위, 골라진 구간 테두리는 z-index = 요소 수 + 1

## 4. 구현 단계 (고정)

**진행 방식 (2026-09-26 해성):** 한 단계씩 한다. 단계마다 채팅 Claude가 로그인한 크롬으로 실제 확인한 뒤 다음 단계로 간다.
한 창(세션)에 한 단계만 하고, 단계가 끝나면 로컬 커밋 + 보고서 + 멈춤. push는 해성 승인 후에만. (자세한 작업 규칙은 CLAUDE.md "스튜디오(/studio) 작업 규칙")
새 단계 프롬프트 전에 3-1 체크리스트와 대조한다. 체크리스트에 없는 기능을 만들거나, 체크리스트 기능을 빼려면 이 문서를 먼저 고친다.

### 11단계 — 요소 (2026-09-26 해성 결정으로 둘로 나눔)

#### 11-1 — 도형·선·화살표
- 페이지 문서에 새 요소 type 'shape'·'line'과 그 칸만 추가(v:1 그대로 — 맨 위 page 모양). 순수 함수 `studioShape.js`(테스트 `test-studio-shape.mjs`),
  페이지 조작 `studioPage.js`(addElementItem·setShapeProps·setLineProps·setLineEnd, readPage가 type별 정리, setItemRect는 선이면 세로 자동)
- 그리기 규칙 하나(화면 SVG `<path d>` = 13단계 캔버스 `new Path2D(d)`): `shapePaintSpec`(채우기 → 테두리), `linePaintSpec`(선 → 끝 모양)
  - 도형 테두리는 안쪽: path를 두께 절반만큼 줄여 그 위에 가운데 기준으로 그림 → 바깥 가장자리가 정확히 w×h. 이음새 네모 = miter, 세모·별 = round(꼭짓점이 밖으로 안 나가게), miterlimit 10(캔버스 기본)
  - 별 = 꼭짓점 5개(안쪽 0.45배)를 자기 네모에 맞춘 뒤 요소 네모로 늘림. 원 = 타원 호 2개. 둥근 네모 = 바깥 반지름 radius(안쪽 path는 radius - 두께 절반)

#### 12-1 — 자르기 · 띠 잘라내기

#### 12-2 — 덮기 (완료)
- **저장 모양**: 지우기와 같은 `edit.layers` 배열 안의 새 종류 (원본 px 정수, `studioCover.js` 맨 위)

  별도 칸(edit.covers)이 아니라 layers에 넣은 이유: ① 덮기는 사진 픽셀을 바꾸므로 완성 JPG에 들어가야 하고, layers가 바뀌면 erase_v가 오르는 기존 규칙(studioFinal)을 그대로 탄다
  ② "지우기 → 덮기 → 지우기"가 섞여도 쌓인 순서대로 계산하려면 한 배열의 순서가 곧 적용 순서여야 한다 ③ 이력·되돌리기·삭제·저장(edit_version 잠금)·서버 final 판단을 고치지 않고 그대로 쓴다.
  studioEdit·studioHistory 주석에 "cover" type이 이미 예약돼 있었다
- **옛 데이터 호환**: 운영 DB의 레이어는 모두 `type:'fill'`(2026-09-26 확인, 45개·사진 8장, type 없는 레이어 0개). type 없는·모르는 레이어는 예전처럼 그리지 않고 보존만 한다(바꾸지 않음).
  지우기만 있는 사진은 계산 계획·key가 예전과 똑같다(AI 결과 조각 key가 바뀌지 않음 — 테스트로 고정)
- **계산 규칙(`studioFillPlan` 일반화)**: 계산 목록 = 지우기 + 덮기(`studioEdit.pixelLayersOf`, 배열 순서). 연결 판정 = "앞 레이어가 쓰는 범위 + RING"이 "내가 읽는 범위들 + RING"에 닿음.
  지우기는 쓰는 곳 = 읽는 곳이라 예전 판정과 같고, 덮기는 읽는 곳이 가져올 곳(+feather)·덮을 곳(+feather) 두 군데. 덮기 한 개 = 두 조각에 연결된 앞 결과를 덮어쓴 뒤 `blendCover`
  (덮을 곳 네모 안 = 가져온 픽셀 그대로, 바깥 feather 띠 = 네모에서 떨어진 거리로 smoothstep 섞기, 모서리 둥글게, 사진 밖 띠는 가장자리 픽셀 반복). AI가 아니라 단색처럼 다룬다(effectiveKey)
- **그리기 경로 모두 같은 함수**: 지우기 화면(StudioCanvas) · 완성 JPG(studioBake → composeErased) · 페이지 작은 사진(studioViewImage — key에 덮기 포함) · 내보내기·미리보기·자르기 창(erasedSourceOf → composeErased).
  자르기·띠(12-1)는 지금처럼 그 위에 나중에 적용 — 덮기 좌표는 자르기 전 원본 기준. 덮기만 있는 사진도 완성 JPG를 만든다(requestBake)
- **화면**: 지우기 화면 도구 [선택][붓][네모][덮기](C). [덮기] = ① 덮을 곳 네모 → ② 가져올 곳 점선 네모가 옆에 자동(오른쪽 → 왼쪽 → 아래 → 위, 간격 feather+4, `autoSource`) →
  끌면 덮을 곳에 바로 미리보기(같은 계산 함수, 한 프레임에 한 번) → 가장자리 슬라이더 → [적용](이력 "덮기")/[취소]. 가져올 곳은 사진 밖으로 못 나감(끌기·저장 모두).
  적용한 덮기: 네모 옮기기·크기(이력 "영역 이동"/"크기 조절"), 가져올 곳 옮기기(이력 "가져올 곳 옮기기"), 가장자리(이력 "덮기 가장자리"), [선택한 덮기 삭제]·Delete(이력 "영역 삭제"), 되돌리기·다시 = 지우기와 같은 사진 이력.
  [원본 보기]를 누르고 있으면 덮기 전 원본. 왼쪽 아래 "적용한 순서" 목록(1 덮기 / 2 지우기 · 단색 …, 누르면 고름)

## 5. 1단계 SQL (해성이 직접 실행)

```sql
-- 스튜디오 페이지 문서 저장 자리 (구간 순서·높이·요소·템플릿 정보)
-- 대상: euccompany (kkqxdvytjcwqiditkqay) / 새 테이블이 아니라 컬럼 추가 → 2026-10-30 GRANT 규칙과 무관
-- 영향: studio_projects에 컬럼 2개 추가. 기존 행은 page=null, page_version=0. 다른 테이블·정책은 건드리지 않음.
begin;

alter table public.studio_projects
  add column page         jsonb,
  add column page_version integer not null default 0;

alter table public.studio_projects
  add constraint studio_projects_page_shape
    check (page is null or (jsonb_typeof(page) = 'object' and page ? 'v')),
  add constraint studio_projects_page_size
    check (page is null or octet_length(page::text) <= 1000000);   -- 1MB 상한 (추정값)

-- 컬럼 단위 UPDATE만 허용 (테이블 단위 UPDATE 금지 원칙 유지)
-- RLS: 기존 "studio_projects update: own" 정책이 그대로 적용됨 → 새 정책 없음
grant update (page, page_version) on public.studio_projects to authenticated;

commit;

-- 검증 (읽기 전용)
select column_name, data_type, column_default from information_schema.columns
 where table_schema='public' and table_name='studio_projects' and column_name in ('page','page_version');
select string_agg(column_name, ', ' order by column_name) from information_schema.column_privileges
 where table_schema='public' and table_name='studio_projects' and grantee='authenticated' and privilege_type='UPDATE';
-- 기대: deleted_at, page, page_version, title
select count(*) from information_schema.role_table_grants
 where table_schema='public' and table_name like 'studio%' and grantee='authenticated' and privilege_type='UPDATE';
```

## 6. 저장소 SQL 기록 누락 (결정 14)

`supabase/studio_schema_2026-09-24.sql`에는 없지만 운영 DB에는 이미 반영돼 있는 변경 (2026-09-25 information_schema·pg_constraint 읽기 전용 조회로 확인).
"내 사진 올리기"(upload 프로젝트) 기능과 함께 들어간 것으로 보인다. 실행 SQL 원문은 저장소에 없다 — 아래는 **현재 상태 기록**이며 재실행용이 아니다.

|---|---|---|
| `studio_projects.source_type` | 없음 | `text not null default '1688'`, `check (source_type in ('1688','upload'))` |
| `studio_projects.offer_id` | `not null`, `check (offer_id ~ '^\d{9,16}$')` | nullable. `studio_projects_offer_id_check`: `(source_type='1688' and offer_id is not null and offer_id ~ '^\d{9,16}$' and source_url is not null) or (source_type='upload' and offer_id is null)` |
